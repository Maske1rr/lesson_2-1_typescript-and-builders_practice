# 2/1. TypeScript и сборка: практика

**60 минут: TypeScript (30) + сборка (30).** Один проект, без backend. В стартовой версии каждая заявка означает одного участника. Добавьте группы от 1 до 5 человек и подготовьте проверенную сборку.

## Запуск

Нужны Node.js **22.12+** (проверено на 22.22.2) и npm **10+**. Откройте терминал в этой папке:

```bash
npm ci
npm run dev
```

Откройте адрес из терминала. Зависимости желательно установить до пары. Используйте Vite, а не Live Server. Если npm не найден, проверьте установку Node.js и откройте терминал заново.

В `src/main.ts` находятся модель, расчёт, обработчик и готовый интерфейс. Метки А1–Б3 показывают места работы. Исходная версия проходит `npm run typecheck`; доработки перечислены ниже, скрытых багов искать не нужно. Все изменения делайте в своей копии проекта.

## А. TypeScript · 30 минут

### А1. Модель · 8 минут

Замените выведенный `type Booking = ...` на `interface Booking` с полями `id`, `name`, `seats`, `status`. Для статуса создайте `type BookingStatus = 'new' | 'confirmed'`. Аннотируйте `initialBookings` как `Booking[]`; объявления типов разместите перед массивом.

Наведите курсор на `rawName` в обработчике: как меняется тип после проверки? Запустите `npm run typecheck`.

**Готово:** модель соответствует двум исходным заявкам, проверка проходит.

### А2. Функция · 7 минут

У `countSeats` явно задайте вход `Booking[]` и результат `number`. Вместо длины массива посчитайте сумму `seats` через цикл или `forEach`.

Временно добавьте `const total: string = countSeats(bookings)`. Прочитайте ошибку: что ожидалось и что получено? Исправьте аннотацию. Затем сами воспроизведите и исправьте несовместимость: задайте `seats: '2'` в одной исходной заявке.

**Готово:** у исходных заявок с `seats: 2` и `seats: 1` сумма равна 3. После проверки верните обеим `seats: 1`.

### А3. Ввод · 9 минут

Замените заглушку `readSeats`. Она получает `string | File | null`, возвращает допустимое число или `null`. Сначала проверьте строку и непустое значение, затем преобразуйте через `Number` и проверьте целое число от 1 до 5. Обработчик уже показывает ошибку и создаёт заявку.

Поле намеренно текстовое: неверные значения должны доходить до вашей проверки. `novalidate` отключает встроенную проверку формы, чтобы её не принять за работу своего кода.

| Ввод участников | Ожидание |
| --- | --- |
| `2`, `1`, `5` | Новая карточка, счётчик увеличился на указанное число |
| Пусто, `2.5`, `0`, `6`, `abc` | Сообщение об ошибке; список и сумма не изменились |

В каждом случае укажите непустое имя. Если нужна подсказка по синтаксису, откройте [справку](СПРАВКА.md).

**Готово:** правила выполняются в интерфейсе; `typecheck` проходит. `any`, подавление ошибок и отключение `strict` не заменяют исправление.

### А4. Параметр типа и изменение модели · 6 минут

Объясните связь `Array<Booking>` и `Booking[]`. Временно вызовите `bookings.push('ошибка')`, прочитайте диагностику и удалите вызов.

**Самостоятельно:** добавьте обязательное поле `source` с единственным допустимым значением `'web'`. Сначала предположите, какие места изменятся. Согласуйте модель, исходные данные и создание заявки, покажите источник в карточке. Новое поле формы не нужно.

**Готово:** типы проверены, источник виден у старых и новых заявок. Отметьте для себя: самостоятельно / с подсказкой / не завершено.

## Б. Сборщики · 30 минут

### Б1. npm и проверка перед сборкой · 7 минут

В `package.json` найдите зависимости Vite и TypeScript, команды `dev`, `typecheck`, `build`, `preview`. Объясните соседу разницу между пакетом и npm-командой, назначение `package-lock.json`.

Сейчас `build` запускает только Vite. Измените команду на `npm run typecheck && node node_modules/vite/bin/vite.js build`. Проверьте её запуск.

**Готово:** перед сборкой выполняется `tsc --noEmit`; конфигурация `strict` сохранена.

### Б2. Модули · 8 минут

Перенесите `Booking` и `BookingStatus` в `src/models/booking.ts`, а `countSeats` в `src/lib/count-seats.ts`. Каркас файлов уже есть. Добавьте `export`, `import type` для модели и обычный `import` для функции. Удалите перенесённые объявления из `main.ts`; `initialBookings` остаётся там.

**Готово:** код разделён, типы проверены, добавление заявки и сумма работают как раньше.

### Б3. Изображение · 6 минут

В `main.ts` импортируйте `./assets/workshop.svg` как URL. В отмеченном месте задайте `logo.src` и `logo.hidden = false`; элемент уже найден и проверен. Добавьте подходящий `logo.alt` или оставьте пустым, если считаете изображение декоративным. Проследите импорт `style.css`.

**Готово:** изображение видно; вы можете показать, какой импорт подключает каждый ресурс.

### Б4. Сборка и приёмка · 9 минут

1. Временно верните `seats: '2'` в исходные данные. Запустите `npm run build`: команда должна завершиться ошибкой типов. Старый `dist`, если он есть, при этом может остаться.
2. Исправьте значение. Выполните `npm run build`, затем `npm run preview`. Откройте именно адрес preview из терминала.
3. После перезагрузки сумма равна 2. Добавьте Анну с 5 участниками: сумма станет 7, появится новая карточка с источником `web`. Попробуйте добавить 6: сообщение об ошибке, сумма остаётся 7. Проверьте картинку и стили.
4. Уберите временные диагностические строки и текст о стартовой версии в интерфейсе; обновите подсказку поля. Повторите сборку после последнего изменения.

**Готово:** `typecheck` и `build` успешны, собранное приложение выполняет требования. Изменение исходников не обновляет preview без новой сборки.

## Что показать преподавателю

Работающий preview, разделённые модули, успешный `build` и его отказ при ошибке типов. Коротко объясните, почему тип `number` не заменяет проверку диапазона. Отдельный отчёт или видео не нужны. Если сдаёте через Git, сохраните исходники и lockfile; `node_modules` и `dist` не коммитьте.

Успели раньше? Проверьте ввод с пробелами и объясните поведение. Затем измените верхнюю границу до 8 и повторите проверки для 8 и 9. Новые инструменты для этого не требуются.
